# Вакансии и письма на сегодня

Работаешь в репозитории JobHuntAssistant. Репозиторий публичный: ничего из папки выгрузки, резюме и `.env` в git не добавляй и не коммить.

## Шаги

1. Определи папку выгрузки: `OUTPUT_DIR` из `.env`, иначе `~/Documents/JobHunt`.
2. Если папки `<OUTPUT_DIR>/<сегодня YYYY-MM-DD>` нет или в ней нет `vacancies.md`, запусти сбор:
   `python run.py` (на Windows из venv: `.venv\Scripts\python run.py`). Если все источники пропущены — сообщи причины из лога и остановись.
3. Прочитай резюме: `RESUME_PATH` из `.env`, иначе `<OUTPUT_DIR>/resume.md`. Нет резюме — попроси положить его туда и остановись. Письма без резюме не пиши.
4. Прочитай `<OUTPUT_DIR>/<сегодня>/vacancies.md`.
5. Для каждой вакансии реши: подходит / частично / не подходит (одна строка «почему», по требованиям вакансии и фактам из резюме).
6. Для «подходит» и «частично» напиши письмо:
   - 5–7 предложений, обращение без «Уважаемые господа»;
   - 2–3 конкретных факта из резюме, которые закрывают требования вакансии (цифры, системы, оборудование);
   - никаких навыков, которых нет в резюме; если требование не закрыто — честно: что уже есть близкое и как быстро доберёшь;
   - без шаблонов «идеально подхожу», «команда профессионалов»;
   - в конце контакты одной строкой из резюме.
7. Запиши результат в `<OUTPUT_DIR>/<сегодня>/letters.md` в формате:

   ```
   ## <N>. <Вакансия> — <Работодатель>
   Ссылка: <url>
   Оценка: подходит | частично | не подходит — <почему>

   <письмо>
   ```

8. Ничего не отправляй и не откликайся сам: отклики пользователь делает вручную. В конце выведи короткую сводку: сколько подходит, сколько частично, путь к `letters.md`.
